# ApxInf4.0：Thor-U提交在Thor-2的逐项复测

> 本文是原始逐commit A/B的历史记录。当前Final已把三组优化设为默认路径，并删除对应开关，当前提交与默认路径重新编译、110轮模型复测见[Final默认性能路径交付](APXINF4_FINAL_DEFAULTS.md)。

Thor-U的warp-prefix＋FFN（ApxInf4.0）在6/6组中含prefill吞吐较Final为正，Decode变化范围+1.99%至+3.19%，含prefill吞吐变化范围+0.88%至+2.67%。继续加入GDN组合后，在6/6组中含prefill吞吐为正；Decode变化范围+4.54%至+6.21%，含prefill吞吐变化范围+2.77%至+5.94%。所有百分比直接来自本轮同机正式对照。纯追加Prefill未确认稳定收益，8K回退在反向复测中仍出现。

本轮4个阶段×11个case，每项2轮预热、10轮计分，共440轮正式请求、88轮预热。前置4K/48K的24轮短测单独保存，不混入正式成绩。

## 硬件、配置和计时

Thor-2，CUDA13.2.86 / driver595.78 / SM110、20SM。GPU GPC min=max1530MHz，CPU各policy固定2601MHz，EMC bwmgr固定4266MHz，逐进程采样核验。1530MHz是已确认的对照频率，当前可用GPU上限为1575MHz。HugeTLB保持0；结束恢复原频率策略。

同一Qwen3.6-35B-A3B-NVFP4检查点、NVFP4 MoE、动态FP8 target KV、FP8 draft KV scale1、greedy、固定MTP depth3、CUDA Graph/full GDN，权重/激活投影精度沿用Final。各stage独立归档实际ELF，保持同一份736个recipe，计时无在线调优或recipe缺失回退。相邻case反转四版本顺序。

Decode输入4/8/16/24/32/48Ki，严格输出1024 token。首token计入TTFT，其后1023个间隔计算Decode tok/s；吞吐用所有正式轮的token总数除以总时间。含prefill tok/s为1024输出token/完整模型生成时间，含prompt prefill、首token和后续decode，排除权重加载、分词和HTTP/AIOS。

追加Prefill为已有4/8/16/32/48Ki KV追加4096输入、输出1 token；计分排除初始KV构建，按正式轮prefill_ms中位数。输入为固定种子的合成token序列。

## 与Thor-U原表的关系

用户原4K表为Final105.87/99.02、warp107.20/100.19、FFN109.28/101.99（Decode/含prefill tok/s）。两机13个模型/配置文件SHA256一致，包括全部3个safetensors分片；但同一4K/1024输入输出规格下，Thor-U基线MTP329轮、验证1316行，输出digest为`5adaafb945679d42`；Thor-2为363轮、验证1452行，digest为`594f45d9fbe5f16d`。跨机器的模型输出和工作量不同，绝对tok/s差值同时包含执行环境与工作量差异，不能直接归为单一commit或硬件收益。

Thor-U原记录为CUDA12.8.93、HugeTLB20480页，长case部分只有3轮测量且48K未完成。本轮统一在Thor-2自身Final上比较；未把旧Thor-U、旧GPU-only Thor-2或历史TRT百分比累加。本轮没有新测TRT，也没有对跨机器输出差异作单一原因归因。

## 正确性、产物和解释收益的证据

每个相同case的四版本、所有预热与计分轮输出digest和完整MTP统计一致，并匹配Thor-2此前冻结golden。14个原检查点文件的inode/大小/mtime前后不变；736个recipe逐字节前后不变。频率、实际ELF和源码身份检查通过。

新增Host API验证通过2个Graph测试和1个真实FFN层测试，覆盖同Session分支、M1/2/3/4、回放、毒化、只读/越界与失败恢复。模型层测试要求冻结recipe；64×64合成Graph语义测试关闭autotune但不作性能计分。GDN精度、状态bank提交/恢复和生命周期证据复用[此前GDN验收](APXINF4_GDN_CANDIDATES.md)。

实际新旧ELF整体哈希不同，因此另行提取CUDA设备模块核验：FFN相对此前de86版本101/101份payload逐字节一致，GDN相对此前b136/8b版本也为101/101一致。可复用此前同算法/设备模块的成对profiler解释：FFN增加独立分支重叠；GDN只读源省去验证前2MiB recurrent初始化复制，prefix-only省去无用末尾快照写回。这些profiler区间不是模型关键路径占比，不用于推算本轮端到端增幅。

首次构建切换曾因保留旧mtime误用缓存，已被链接门禁拦住，未产生性能成绩；相关产物保留为无效构建。修正mtime并重建后，各阶段ELF独立核验。原始CUDA13编译失败也保留为兼容诊断，两者都不计作性能成果。

## 追加Prefill反向复测与未解决项

针对主矩阵的回退项，各新建进程再做2预热＋10计分；8K顺序为Final→GDN，48K顺序为FFN→Final，与主表相应对照反转。两组共40轮正式计分，均通过输出/工作量、recipe、源码、ELF和频率检查，结束恢复原策略。

|---|---:|---:|---:|---:|---:|---:|

本表正数表示更慢。8K GDN两轮均回退，幅度1.70%和4.73%，原因尚未定位；不能概括为全场景加速。48K FFN由主表慢2.18%变为反向快1.94%，该项进程间波动明显，未用复测更好的数字替换主表。纯追加prefill没有稳定新增收益；已确认的加速范围是上述六组1024输出的生成请求。

为解释8K回退拟补一组CUDA/NVTX结构性profile，但另一独立图像输入项目的编译已持有两把共享GPU锁。采集在获取锁处被拦住，未启动GPU、未改频率，不算任何性能成绩，也没有声称已解释回退根因。保留阻塞日志，未打断该编译作业。

本轮总计480轮正式计分（主矩阵440＋反向40），另有24轮短筛选。只读最终审计确认自有进程均已退出、每次原频率策略均已恢复、14个原检查点文件和736份recipe不变、8个归档ELF哈希不变，HugeTLB保持0。当前共享锁由后续独立编译持有，未修改其进程、频率或锁。
