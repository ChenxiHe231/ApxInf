## 改了什么

原 FC2 在私有 `[tokens, top8, hidden]` 槽位上对预先清零的 BF16 值执行 reduce-add。每条有效 route 的每个输出通道只有一个写入者，因此改为保留 `add.rn.bf16x2(value,+0)` 语义后直接 bulk-store，避免先清除整个 expanded 输出，再读改写同一位置。4096 token 时该中间区为 128 MiB；这仅是逻辑大小，不能直接视为实测 DRAM 流量。最后的 top8 顺序 FP32 归约保持不变。

新路径自动限制于 CUDA 编译头版本 >=13.2、实际 SM110、BF16、tokens>4、E256/top8/H2048/I512；小 batch 和其他设备沿用旧路径，无新增开关或环境变量。invalid route 只清其自有槽位为 +0，并在读取 scale 前拒绝无效 expert。token 量化复用仍要求全部 8 条 route 有效且 scale 逐位相同。没有把不安全的简单复制当成 BF16 加零的等价实现。

## 正确性与构建证据

BF16 全部 65536 种位模式的实际加零映射对照通过；原算子 GPU 输出、重复 expert、混合/全无效 ID、只读及 canary 检查通过。实际产品覆盖 M=1/4 的旧路径与 M=5/127/128/129/4095/4096/4097，包含变输入 Graph 和冷进程首次大 batch capture。无效 ID 不输入旧版越界路径，其数值参照采用有效 route 的旧路径和显式 +0 规则。模型严格检查覆盖 4K 输入/1024 输出与 32K+4K append。

实际实验源码为 `d875b94d`，其父版 `b6a440c5`；构建只改变 runner native 成员，新增 AOT 保留原 11 个成员逐位不变，只附加实际 store 对象。GEMM/Attention 身份和冻结 recipe 不变，真实 examples 重新链接；产物包含共同的验证 overlay。`PRODUCER.json` 的 NOT_VALIDATED 是导出时的历史状态，本报告单独记录后续实际模型验收，不倒写导出原件。

配置：NVFP4 MoE、静态 FP8 dense 投影、target 动态 FP8 KV、draft FP8 scale1、greedy/fixed MTP3；Thor3 GPU 1530 MHz，CPU 2601 MHz，EMC 4266 MHz。GPU 最高 1575 MHz，本轮沿用已批准的 1530 MHz。原始文件哈希、逐轮数据、命令与构建身份见 [逐轮证据](evidence/fc2-direct-store-thor3.json)。

## 成对模型 NSys 机制证据

实际 b6/d875 两个产物各跑 2warm1 的 4K+4K append，前置 KV 准备在 API 捕获范围外，输出、MTP 工作量与各自正式 N5 锚一致。40 次 FC1 的 GPU union 为 **74.294112 → 52.528160 ms**，40 次 FC2 为 **66.866144 → 50.354816 ms**，两部分合计少 **38.277280 ms**；各自 union 与 sum 一致。候选实际出现 `kernel_cutlass_kernel_fc2_store_n128…`，与冻结 runner/AOT 身份和大 batch 自动条件共同证明新路径执行。

这组数据解释省略 FC1 expanded 清零、FC2 直接写回的机制；它不是另一项端到端收益，不能与上表百分比相加，也不能证明 DRAM 流量或关键路径占比。成对暖态 NCU 见下节。全部 26 份原件哈希、两份 SQLite、88 个频率样本和恢复均已独立核对。原收集器字段名中的 N10 是历史命名，本次实际比较锚为上表的正式 N5，不给候选补签 N10。

## 暖态 NCU 诊断

同实际模型、application replay、cache control none，各任务有 4 次完整执行，每次 2warm1，配置、完整输出和 MTP 工作量均对齐对应冻结锚。每份 CSV 恰有一个选定 kernel；四个 append 任务各取第一层对应核，不能外推全部 40 层。

|---|---:|---:|---:|---:|---:|
| append 首个 FC1 | 2.039360 ms | 1.402816 ms | 14,857,694 | 10,532,330 | 0→0% |
| append 首个 FC2 | 1.770496 ms | 1.355520 ms | 9,287,665 | 9,287,919 | 9.688619→0% |

FC1 的 L2 miss 与时间下降、FC2 的 atomic-active 指标归零，与移除清零及 reduce-add 路径一致；**FC2 L2 miss 基本不变**，不能声称它减少了 L2 miss，更不能把 L2 指标改称 DRAM 流量或带宽证据。

另一个任务只采实际首个 target verify M4 FC1：147.008 us，L2 hit 3.369978%，L2 miss 1,125,259 sectors。其归属由真实 363 轮×40 层图、源码及 CUDA correlation 独立证明，launch-skip=40 是该 trace 的实数，不沿用旧基线猜测。M4 保留原算子路径，本轮不扩采 M4 FC2。这些都是诊断，不新增端到端收益，不证明 `critical_f`。
