## 改了什么

四抽头 GDN 卷积一次协作处理相邻 4 个 token，在寄存器中保留卷积系数与滑动历史，复用源值。每个 head group 的 token 维 CTA 数从 4096 降至 1024。保持抽头累加次序、SiLU 后 BF16 舍入、Q/K 归一化、F16 输出、alpha 和最终窗口更新流程。只对 `tokens=4096、KH=16、VH=32、D=128` 且输入/输出存储互不重叠的配置自动派发，其他配置沿用原路径；无用户开关或环境变量。

源码父版为 `39784163d32a82ccc059db4f5c519a7dac26c7e0`。实验源码 `b6a440c5bde534fe2384db9da2d8322ce162bdb5` 只改 `gdn_ops.cu`，候选文件 SHA256 为 `64d08fcc11f1da03db0ec01b77cb5b757a7cad8cebdbc4347805d436e927f382`。独立检查确认已有 norm 函数与父版 `f644…` 逐字相同；新增卷积、存储资格及派发函数与已验证算子源码逐字一致。实验提交号仅标明验证来源，卷积独立交付提交为 `81e2e942`，源码与实验版逐字一致。

## 验证与产物

- 算子原始 AB/BA 短筛分别从 **1.187925 → 1.008832 ms**、**1.186496 → 1.004875 ms**，降低 **15.08% / 15.31%**。这是生成数据的 CUDA event 区间，包含 launch 供给空隙，**不是纯 kernel 或模型端到端收益**。
- 算子逐位、有限性、只读与 canary 检查通过；1、4、4095、4097 token 的回退以及 4096 变输入 Graph 4 次重放通过。模型严格检查覆盖 4K 输入、1024 输出 Decode，以及 32K+4K 追加 Prefill；和实际父版的完整 token、FNV 摘要及 MTP 工作量相同。Decode 此处只有正确性检查，不声称加速。
- 构建收据记录仅 `gemm-81fa885e11ea7db4-gdn_ops.o` 变化，其他 native 成员哈希不变，GEMM/Attention ID 与 recipe 不变。父版 native 为 `144e591a…`，候选为 `419f8055…`；真实 Rust examples 重新链接，未移签旧 ELF。Benchmark 产物是对应 Git core 加共同的输入绑定 / 输出 token JSON 验证 overlay，并非未经 overlay 的整仓二进制。
- 配置为 NVFP4 MoE、静态 FP8 dense 投影、动态 FP8 KV、greedy、固定 MTP depth3。Thor3 GPU 实际锁 **1530 MHz**，CPU 2601000 kHz，EMC 4266000000 Hz；原时钟上限 **1575 MHz**，所以本轮没有使用最高 GPU 频率，而是遵守用户批准的 1530 MHz 对照口径。已逐条核实频率样本及恢复配置。

原始模型包 SHA256：`3ecdd89a35a44330c8c2143ed6428b9842ecef82179578ba12673727bd6aac9f`。全部原始输出、配置、完整向量、FNV、工作量、文件哈希已独立重解析；仅两个派生标准差存在跨 Python 的约 `2–4×10⁻¹⁶` 舍入差，原始样本和均值完全一致，未修改原件或精度阈值。精确样本、命令和身份见 [逐轮证据](evidence/gdn-prefill-temporal4-thor3.json)。
